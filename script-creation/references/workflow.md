## 来源

本文档描述**品牌无关**的流程骨架。品牌私有的表 token 与文档 URL 见 `config/<brand>/config.json`
（2026-09-17 配置化：此处不再内联任何品牌资源地址，避免与配置双轨漂移）。

## 飞轮全貌

```
创意洞察 ──[素材传递]──> 脚本创作 ──[复盘沉淀]──> 数据管理
    ↑                                                       ↓
    └──[策略同步]──── 策略标准 <──[数据反哺]────────────────┘
```

## 脚本创作内部流程（当前实现：2 步 + 2 交互点）

本 skill 实现「创意方向生成 → 写脚本」，上游由 `influencer-style-analysis` skill 提供达人风格 JSON。

| 步骤 | 动作 | 产出 | 交互 |
|------|------|------|------|
| 0 | 达人风格分析（外部 skill） | 风格 JSON（含 `career_identity`） | 上游 skill |
| 1 | 创意策略表驱动生成创意方向 | `step3_directions.json`（5 个方向，蹭热点 ≤2） | ⏸ 交互点 1：多选；全不认可 → 回步骤 1 |
| 2 | SOP + 策略库驱动写脚本 + 生成期自检 | `step6_scripts.json` | ⏸ 交互点 2：多选；全不认可 → 回步骤 2 |

> 大纲步骤（旧流程步骤 5）已于 2026-09-09 移除：directions → scripts 直通。
> 旧流程的「匹配风格 + 素材库/历史数据库 → 原始创意」（步骤 2）与 step2 依赖也已退出主流程。

## 步骤 2 的自检口径（2026-09-15 定，**不打分**）

| 环节 | 做什么 | 输出字段 |
|------|--------|----------|
| ① 第 0 条合规红线 | 一票否决，踩线即打回重写 | `compliance_check` |
| ② SOP 检验机制 | 逐项过 pass / fail（开头／删名／达人／速度／链路／密度／切入／热点／口播／合规） | `self_check` |
| ③ 生成期硬约束自证 | 钱要素首现位置、总字数、过渡句数、逐句功能标签串 | `verification` |
| ④ 库内取用留痕 | 各模块库内编号＋命中理由；角色定位有且仅 1 档 | `library_picks` / `material_gap` |

**为什么生成期不打分**：AI 按 SOP 生成的初稿必然「满分」（2 分档写的就是 SOP 的要求本身），自评没有区分度——
既是球员又当裁判。所以：

- **生成期**：只做 pass/fail（第三节③④⑥ 已前移为 SOP 的「生成期硬约束」，写完即达标）
- **打分时机**：只对**人工修改后的版本**打 8 维度「预期分」，且必填改动三要素（位置／性质／幅度）
- **复盘**：预期分 vs 星推比／转化达标 → 归因"哪种人工改动提升最大" → 反哺策略库
- **落点**：预期分与改动记录随脚本交付文档留存（`human_revision` 字段），不落 Base

## 回退机制

- 交互点 1（选创意方向）：全不认可 → 回到步骤 1 重新生成
- 交互点 2（选最终脚本）：全不认可 → 重新执行步骤 2（换方向或换打法）

## 数据流

```
influencer-style-analysis JSON
        ↓
步骤 1 ← 创意策略表（飞书）+ 热点素材库 + 网络素材库
        ↓
5 个创意方向（蹭热点 ≤2）
        ↓
步骤 2 ← 两份 SOP + 两份策略库 + 评分标准（运行时实时拉取，不缓存）
        ↓
脚本 + 合规检查 + self_check + verification + library_picks
        ↓
输出：选中脚本 JSON（human_revision 留白待人工填）
```
