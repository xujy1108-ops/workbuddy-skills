# 创意内容分析工作流

## 概述

围绕品牌核心场景（如度小满的"资金周转困难"），从抖音搜索真实用户内容视频，提取完整脚本，分析创意价值，为广告植入提供建议，最终将结果同步到飞书多维表格。

**一条命令跑完全流程**：查重 → 生成关键词 → 搜索抖音 → 提取脚本 → 分析创意 → 写入飞书表格 → 飞书通知执行结果。

当前支持 **抖音** 渠道。小红书和微信渠道后续补充。

## 品牌配置化（2026-09-16 改造）

所有品牌私有内容外置在 `config/<brand>/`，代码零品牌硬编码；换个品牌 = 新增一个配置目录：

```
config/
  duxiaoman/
    config.json            # 品牌名/飞书表 token/素材id前缀/渠道名/过滤禁止词/
                           # 处境坐标系（人群轴×时刻轴）/邻接域/策略清单静态快照/关键词来源片段
    prompts/
      keyword.md           # 关键词生成 prompt 模板（占位符：__TOTAL__ __SOURCES__ __STRATEGY_LIST__
                           #   __EXPLORE_MATERIAL__ __RECENT_KEYWORDS__ __HIT_RATE_FEEDBACK__ __EXAMPLE_ITEMS__）
      analysis.md          # 创意分析 prompt 模板（占位符 __DIRECTION_ENUMS__）
      comment_analysis.md  # 评论分析 prompt 模板（占位符 __DIRECTION_ENUMS__）
  weiyedai/
    (同结构骨架，待补齐)
```

- **品牌选择**：`--brand <name>` 参数 > env `WORKFLOW_BRAND` > 默认 `duxiaoman`
- 配置缺失/缺必填字段/模板文件缺失/值仍为 `TODO_` 占位（骨架未补齐）/模板为纯注释 → 启动即报错并列出可用品牌，不会白烧 API
- env 变量（`BITABLE_BASE_TOKEN` 等）可覆盖品牌配置里的表 token 默认值
- 运行状态文件（关键词统计/近期词/探索登记表）按品牌隔离在 `.state/<brand>/`，首次运行自动从根目录旧文件迁移
- 新增品牌步骤：复制 duxiaoman 目录 → 改 config.json（品牌名/表 token/过滤词/坐标系）→ 改 3 个 prompt 模板中的品牌段落 → 无需改任何代码
- **配置与飞书表对齐口径**（新增品牌/改表后必做）：
  - `tables.*.baseUrl` 只作核对用（点开即可对表），实际调用只用 `baseToken` + `tableId`
  - 策略清单**实时读策略表**，不做本地镜像；`strategy.fallbackStrategies` 只是读取失败时的静态快照，口径 = 策略表全量行副本（含 `excludeL1` 行，运行时过滤）
  - `strategy.fallbackDirectionEnums` 的一级/二级枚举必须与策略 Base「内容方向一/内容方向二」字段的 select 选项逐项一致（忽略带换行的脏重复选项）
  - **方向值归一化兜底**：脚本读表、AI 回填、落表前均对「内容方向一/二」做空白归一化（`normalizeDirectionValue`，折叠空格并 trim）。飞书 select 按全字符串精确匹配、不做 trim，若 AI 吐出带换行的方向值会被当成新选项落表，导致同一方向分裂成两个选项。Base 侧若已有带换行的脏选项（如 `中年人借网贷不是堕落\n`），属历史脏数据，建议手动删除

## 执行方式

### 完整运行（默认）

```bash
node scripts/run_workflow.js --brand duxiaoman
```

这一条命令会自动完成全部步骤：
0. **飞书预检** — 任何付费 API 调用（LLM/TikHub）之前，先用 lark-cli 探活素材库和策略表（各拉 1 条记录），任何一个不可访问立即中止并给出排查方向——杜绝「整轮跑完才发现飞书不可用、白烧 API 资源」
1. **自动查重** — 用 lark-cli 从飞书多维表格拉取已有素材 ID
2. **生成关键词** — DeepSeek 按动态配额生成 4 个抖音搜索关键词：①策略直搜（运行时实时读**策略表**，把策略行翻译成用户会搜的词，不按等级过滤，整类排除「回应解释」）②策略衍生（抽象策略核心钩子公式，换人群/职业实例化）③开放探索×2（2026-09-16 探索策略重构，多配额块组合）：**配额A 热点翻译**（热点素材表 0-1 跳新鲜热点，跳数门控+同义去重，翻成热点牵出的用钱处境词；无 0-1 跳热点时由坐标系补位）+ **配额B 邻接域反推**（「缺钱但没借钱的人怎么办」反推域：卖黄金/典当/亲友开口等，话题自带缺钱语境，供给新钩子公式）；加强模式第 3 个配额为**处境坐标系**（人群×缺钱时刻格子，借钱需求原生场景，格子由 `.explore_ledger.json` 登记轮转、扫过即销）。探索措辞铁律：处境化（具体的人+具体的难处），禁止议题化（"XX该不该/怎么看/贬值"）。**加强模式**：连续 2 轮零新策略产出（无新建方向且无追加打法）时自动切换为 直搜1 + 探索3、策略衍生暂停，打断"关键词←策略表→验证老策略"的闭环
3. **搜索抖音** — TikHub API 搜索视频，**排序方式为「综合排序」（`sort_type=0`，2026-09-16 应用户要求由「最多点赞」改为综合排序：资金周转题材上点赞与贴题度负相关，最多点赞会把贴题的中小账号内容挤下去、留下跑题爆款）**，按 cursor 翻页，默认取 1 页即 10 条/词，跨页去重
4. **过滤去重** — 过滤视频文件 > 50MB、导师说教/成功学/负债翻身类标题、公检法/政府人群类标题、房贷断供类标题、看病/上学/结婚彩礼类标题、去除已有素材（**点赞门槛已于 2026-09-16 取消**，`MIN_DIGG_COUNT` 默认 0，改由第 7 步 AI 相关性判定兜底）
5. **提取脚本** — 豆包模型转录视频台词，同时输出表现形式/语速/说话风格元信息（Promise.all 并行，并发 3）
6. **过滤无效内容** — 跳过全程未开口说话的视频、跳过催收/医疗/上学/结婚彩礼等敏感场景、跳过公检法/政府人群相关内容、跳过房贷断供/法拍类内容
7. **分析创意** — DeepSeek 先判断内容相关性（强相关/弱相关/不相关）与时效性（长青/时效话题-未过气/时效话题-已过气），再输出内容方向、素材逻辑、借鉴点、植入建议、适配达人分析、内容策略分析（内容方向一/二 + 植入策略，按内容策略表填写指南）；弱相关/不相关、或时效话题已过气（平台功能红利期/阶段性热点已退，如抖音小店先采后付）的内容自动跳过不写入飞书；长青话题（借钱伤感情、求人不如靠自己等）不受发布时间限制，老素材反而沉淀好。**方向枚举动态化（2026-09-15 反内循环改造）**：分析 prompt 的内容方向一/二枚举运行时从策略表现有方向拉取（含各方向素材数），素材数 ≥5 的饱和方向注入"切入角度实质不同时优先新建二级方向"指令——避免新素材被硬塞进老方向导致策略表不生长；策略表读取失败用内置兜底枚举
8. **高赞评论创意策略分析（独立第二条线）** — 本轮新入库视频点赞 > 3万时，并行触发：抓取该视频高赞评论 → 过滤（无效/禁止方向/去重，同脚本分析逻辑）→ 相关性判断 → 强相关才分析 → 产出与脚本分析同结构的创意策略（内容方向一/二 + 植入策略），沉淀到现有策略表；素材链接ids 中评论洞察来源的 id 带「（评论洞察）」标记便于区分
9. **自动写入飞书** — lark-cli 将结果写入多维表格（含搜索关键词、适配达人、更新时间字段）
10. **内容策略沉淀** — 按内容方向一/二聚合（脚本来源 + 评论洞察来源合并），同方向补充植入策略并追加素材链接ids，新方向新建策略行（等级 X）
11. **策略库生长统计（反内循环预警）** — 每轮记录新建方向数/追加新打法数/仅并入素材数到 `.strategy_growth.json`；「新策略」= 新建方向 + 追加打法，本轮有策略产出但新策略为 0 记一轮旱灾，连续 2 轮旱灾触发加强探索模式并在通知中预警
12. **飞书通知** — 每次运行结束自动给飞书发消息，汇报成功/放弃/失败数量与策略沉淀明细（新建/追加/仅并入）；余额不足时额外提示；内循环预警时提示配额已自动提升

### ⚠️ 必须前台运行（2026-09-08 实测教训）

**禁止把 run_workflow.js 丢到后台/沙箱任务里跑。** 原因：沙箱会拦截 lark-cli 的 keychain token 刷新（`refresh-storage-probe.enc` rename 报 operation not permitted），引发连锁故障——① 飞书写入全部失败；② Step 1 已有素材查询失败 → 脚本现在会**直接中止**（防重复入库，旧行为是静默跳过去重，曾导致 0814 老素材重复入库）。脚本已加 **Step 0 飞书预检**（付费 API 前探活两张表），在此环境下会在启动后几秒内中止，不会白烧 API 资源。

正确姿势：前台直接跑 `set -a && source .env && set +a && node scripts/run_workflow.js`。若必须长任务，确认宿主环境未限制 lark-cli 的 keychain 访问。

### 断点续跑（沙箱中断后恢复）

如果运行被沙箱中断（Exit 137），加 `--resume` 重新运行即可：

```bash
node scripts/run_workflow.js --resume
```

脚本会从 checkpoint 文件恢复候选列表，跳过已处理的视频，只处理剩余的。全部处理完后自动清理 checkpoint。

## 自动化行为说明

### 并行执行
Step 4 的视频脚本提取 + 创意分析使用 `Promise.all` 并行执行（默认并发 3）。单个任务出错不影响其他任务。

### 关键词命中率反馈与方向/来源休眠
脚本自动维护 `.keyword_stats.json`，记录每个关键词的搜索数/初筛通过数/最终成功数、所属方向（direction）与来源（source：strategy_direct/strategy_derive/explore_hotspot 热点翻译/explore_coordinate 处境坐标系/explore_adjacent 邻接域反推；explore_ai/explore_suggest/explore_comments 为历史遗留值）：
1. **低效关键词黑名单**：连续 2 次运行零产出的关键词，下次生成关键词时注入 prompt，禁止 AI 再生成相同或高度相似的词
2. **方向休眠轮换**：某方向累计用过 ≥2 个不同关键词且总产出为 0，该方向进入休眠期，生成关键词时提示 AI 暂停选择该方向（含衍生变体）
3. **来源休眠提示**：某来源累计 ≥2 个关键词且总产出为 0，休眠提示注入 prompt（探索来源已细分：explore_hotspot 热点翻译 / explore_coordinate 处境坐标系 / explore_adjacent 邻接域反推，休眠判定按子来源各自统计）
4. 统计只保留最近 40 个关键词；API 余额不足中途终止的运行不更新统计（避免失真）

### 策略清单动态读取（唯一权威源 = 策略表）
关键词来源1/2 的策略清单**一律以策略表（飞书多维表格）为准**，运行时用 lark-cli 实时读表（`base +record-list`，无缓存），纳入策略表全部行、整类排除 `tables.strategy.excludeL1`（默认「回应解释」——接广告后的回应内容不是可搜的素材场景）：
- 不按等级过滤：S=已验证成功 / A=可继续尝试 / X=工作流自建·待验证（B 级只出现在被排除的「回应解释」类）
- 表里新增/改名/升降级方向，下一轮自动跟上，代码与配置都不用改；也不再存在 24h 缓存的滞后
- 读取失败 → 退到 `strategy.fallbackStrategies` 静态快照（口径：策略表全量行副本，运行时同样按 `excludeL1` 过滤）
- 策略表在单次运行内只读 2 次：Step 1 读一次（策略清单 + 方向枚举共用同一份快照），Step 6 写表前再实时读一次（绝不用旧快照做合并写入）
- **口径边界**：`fallbackDirectionEnums`（方向枚举，喂分析 prompt）镜像策略表**字段选项**，因此包含 15 行方向；`fallbackStrategies`（策略清单快照，喂关键词 prompt）镜像策略表**全量行**。两者都不是「文档镜像」——内容策略文档已废弃，不再作为任何数据源

### API 余额不足处理
检测到 HTTP 402 / quota / insufficient 等错误时：
1. 设置 `quota_exhausted: true`，剩余未开始的任务自动跳过
2. 已成功的结果继续写入飞书多维表格
3. 飞书通知中额外标注"API 余额不足，工作流已提前终止"

### 飞书通知
每次工作流运行结束（无论成功/失败/余额不足），都会自动给当前用户的飞书发一条消息，内容包含：
- 搜索关键词
- 成功 / 放弃 / 失败 数量
- 飞书写入数量
- 内容策略沉淀数量（新建/更新行数）
- 余额不足时附加提示

### 内容策略沉淀（Step 6）
创意分析时 AI 会额外产出「内容策略」子对象（内容方向一/二、方向定义、植入策略、适合达人），分析方法按《内容策略表字段填写指南》（https://kwza968lz1u.feishu.cn/docx/SuLudPWPDoz0ZcxLFwccZpKNnqh）：
- 内容方向一/二**优先复用**策略表已有枚举（一级 10 个、二级 15 个）；当素材核心叙事在对应层级枚举中确实找不到容身之处时，AI 可新建一级或二级方向（新建时在「方向定义」开头注明【新建方向】+理由，命名与现有枚举风格一致）
- 运行结束后脚本自动同步到策略表（token 来自品牌配置 `tables.strategy`，env `STRATEGY_BASE_TOKEN`/`STRATEGY_TABLE_ID` 可覆盖）
- **唯一性判断标准：内容方向一|内容方向二 组合**
  - 同方向已有策略行 → **先查重再补充**：用 LLM 判断每条新素材的「打法+推理链」与已有策略是否同一套逻辑——重复的只把素材 id 并入「素材链接ids」（用、分隔），不追加段落；有实质差异（不同情绪入口/论证路径/植入时机）的才追加「【素材补充 dy_xxx】+ 新打法」段落。查重失败时只并入素材链接ids、不追加任何策略文字（宁少勿堆：追加错误的重复段是粘性的，需人工清理；错过的真新策略仍可从素材库追溯）。**同时合并「适合达人」**：新素材（含查重为重复、只并入 ids 的素材）的达人类型若在行上未覆盖，自动并入「达人类型：」行；**粒度遵循「宽一级优先」**——行上有一级类型则其下二级都视为覆盖；新素材判定为一级类型（如「剧情」）而行上只有它的二级窄类型时，把窄类型收敛为该一级类型；无新类型则不改该字段
  - 同方向新出现 → 新建策略行：策略等级固定 X（创意洞察未验证），正向案例填完整脚本原文，素材链接ids 填本轮该方向全部素材 id；多条素材时同样先查重，以第 1 条为基准去重
  - **新建方向落表**：飞书 select 字段不会自动创建不存在的选项（写入报 800030005），脚本在写入前自动调用「field-get 读全量定义 → 追加新选项 → field-update 全量 PUT」扩充「内容方向一/二」的选项；扩充失败则跳过这些新方向写入并记日志
- 同步失败不影响主流程，仅记录警告

### 飞书多维表格写入
脚本通过 `child_process.execFileSync` 调用 `lark-cli base +record-batch-create` 自动写入。字段映射（素材id前缀、素材渠道、「对品牌」字段名均来自品牌配置 `bitable` 段）：

| 字段名 | 写入值 |
|--------|--------|
| 素材id | 品牌配置 `bitable.materialIdPrefix`（duxiaoman: `dy_`）+ aweme_id |
| 素材渠道 | 品牌配置 `bitable.materialChannel`（duxiaoman: `抖音`） |
| 关键词 | 搜索该素材时使用的关键词 |
| 素材链接 | `https://www.douyin.com/video/` + aweme_id |
| 素材脚本文案 | script 字段完整内容 |
| 内容方向 | analysis.内容方向 |
| 场景 | analysis.场景（多选，从枚举中选，可多选；程序侧 formatScenes 过滤掉自创值）。枚举：对镜口播 / 酒席饭桌 / 居家室内 / 职场办公 / 户外街头 / 店铺商户 / 车内出行 / 线上通话 / 工地工厂 / 其他。**纯对镜讲述（博主/讲师对镜、无场景情节）必须标「对镜口播」，不要混进「其他」**；该字段供 script-creation 按达人拍摄能力匹配素材、并在创意方向里输出场景要求 |
| 内容分析 | analysis.素材逻辑分析 |
| 广告可借鉴点 | analysis.对品牌的借鉴（字段名取品牌配置 `bitable.borrowInsightField`，duxiaoman 为「对度小满的借鉴」） + "\n\n" + analysis.植入修改建议 |
| 适配达人 | analysis.适配达人 5 个子项格式化为多行文本（达人类型 / 表现形式 / 语速与风格 / 口吻 / 推荐达人类型）。达人类型按「度小满-达人类型基础标准」（财经5类/三农2类/剧情2类），必须从 9 个标准类型中选范围最接近的一个，禁止自创类型；**粒度规则：整个一级类型都适合只输出一级分类（如「财经」=财经下所有二级都适合），仅当适配范围限定在某二级类型时才输出「一级-二级」（如剧情-剧情搞笑）** |
| 更新时间 | 写入时的日期（yyyy/MM/dd 格式字符串） |

## 汇总报告

脚本执行完毕后，AI 向用户展示：
- 搜索关键词
- 搜索到的视频总数
- **成功**：N 条（已写入表格）— 列出标题 + 链接
- **被放弃**：M 条 — 列出原因（视频文件过大 / 点赞不足 / 标题禁止 / 重复 / 全程未开口 / 禁止内容 / 内容弱相关 / 余额不足未开始）
- **执行失败**：K 条 — 列出错误信息
- 飞书写入结果
- 如果 `quota_exhausted: true`，标注"⚠️ API 余额不足，工作流提前终止"

## 单独使用视频脚本提取

如只需提取单个视频的脚本（不跑完整工作流），可直接使用 `scripts/video_script.js`：

```bash
node scripts/video_script.js "https://视频下载链接"
```

该脚本支持远程 URL 和本地文件路径。直传链接失败时会自动下载视频到本地，以 base64 方式重试。
